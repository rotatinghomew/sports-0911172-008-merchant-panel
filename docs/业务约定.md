# 当前业务约定

缺报金额为 null，真实零销售为 reported 且 cents=0。merchant 的 successors 记录拆并承接。summary 仅汇总指定集合原始报送；release 是人工审核后的固定内容。可比增长分析见 growth，对外简报的联合披露保护见 disclosure，版本与更正联动见 distribution。

## 数据与一致性

金额均为整数分；日期使用零补齐的日期或同一时区时间字符串，跨时区输入应由调用方先规范化。所有 ID 为业务编号。写入会增加修订并保留旧值，历史 `recorded_at` 是登记时间，不等于事实发生时间；不能据此推断未观测到的业务事实。

单次业务操作是一个事务，失败不留下中间结果；整份回放按顺序逐项执行，前一项成功不会因为后一项失败而撤销。现有重复编号拒绝语义及已完成状态的重试语义由业务操作维护。操作台 JSON 中 `results` 是操作结果，`state` 为当前业务记录；历史以 `Store.history` 查询，当前状态与历史不能混为一谈。

直接方法调用和本地操作台使用相同的业务服务。`data/demo.json` 展示一条正常经营路径，`data/briefing.json` 展示赛事周可比分析、披露控制与更正版本链；两者都是合成样本，不代表总体人群，不能用来宣称任何统计规律。扩展分析时应另外构造能辨别缺失、覆盖和信息时间的样本，不得把样本中的关联直接当成因果结论。

## 可比增长分析（growth.analyze）

分析人员以 `merchants` 显式选择研究范围，基期周与对比周为 ISO 周（如 2026-W44）。口径如下，全部写入结果实体的 `assumptions`：

- 报送单元：生效日介于两期之间的拆并，按 successors 把前后门店合并为一个单元比较，拆并本身不产生进入或退出；承接门店不在研究范围时按退出处理并在 `coverage.unscoped_successors` 列明。
- 同店口径：单元两周的全部在营成员均已报送。在营按营业区间与周有交集判断（closed 为排他端点）。
- 分解恒等式：面板总变化 = 同店变化 + 进入 − 退出 + 部分缺报单元的已观测变化。进入指基期无在营成员（新开业或新接入），退出指对比期无在营成员。
- 缺报是未知不是零：缺报商户不进入任何总额；部分缺报单元的已观测金额单列，不并入同店，也不按零处理；`coverage.missing_reports` 逐户列出。
- 同店变化再分解为营业天数效应与日均经营效应（Bennet 对称分解，取整到分，残差计入日均项）；任一周营业天数为零的单元不参与该分解，其变化单列。
- 行业构成：同店单元按基期行业汇总贡献，给出平均增速基准与超额（excess），跨行业承接单元列 mixed；进出单元同时按行业分列。
- 结果仅描述所选报送面板。`warnings` 在同店覆盖不足、非可比部分占主导时给出提示；任何使用方不得把面板总变化表述为全城消费增长。

分析实体记录全部输入（报送与商户档案）的修订号，供发送前校验。

## 联合披露保护（disclosure.assess）

披露计划由若干单元格组成：`{name, recipients, terms}`，每个 term 为 `{week, sign?}` 加一种选择器（sector / district / merchants / units: paired|entry|exit|partial，缺省为全范围）。披露周必须落在分析的两周之内。规则（`rules` 可覆盖默认值）：

- 最小商户数 `min_merchants`（默认 3，仅支持 2 或 3）：单元格覆盖商户数不足即隐藏。
- 集中度 `dominance`（默认 0.5）：全正系数水平单元格中单一商户占比超过阈值即隐藏。
- 联立差分：对同一收件人，把本次候选内容与该收件人历史已发送内容（含旧版汇总，按范围上限还原）合并，精确检查是否有单个商户金额或少于阈值的商户组合可被线性推导；有则隐藏候选单元格。
- 互补隐藏：被隐藏内容若能由其余内容联立推出，则继续隐藏其余内容直至安全——不只藏一个格子。贪心选择消除违规最快的单元格，按违规数、覆盖商户数、计划顺序决胜。
- 隐藏不偷换统计对象：被隐藏单元格保留名称与对外安全的原因（阈值、集中度、联立差分、互补隐藏），简报中如实说明。

评估假设写入结果：按收件人独立检查，不防范收件人之间的串谋；历史已存在且无法收回的暴露记入 `pre_existing` 告警。可安全披露的部分照常给出可用结果。

## 分发与版本（distribution）

- `distribution.prepare` 接受 `summary`（旧版原始汇总）或 `disclosure`（披露评估）之一。披露路径的收件人取自评估结果，传入 `recipients` 时必须一致；`supersedes` 关联被替代的已发送版本，版本号递增。
- `distribution.send` 发送前复核：分析实体与评估实体未被替换、全部输入修订号未变、报送集合未新增、披露环境（含此后发出的其他简报）仍然安全。任一不满足即拒绝，未发出的内容必须跟随当前有效分析重新评估与准备。
- `submissions.correct` 与 `panel.merge` 之后，已发送且输入受影响的版本保留原内容，状态标记 `corrected` 并追加更正来源；替代版本发出后旧版再标 `superseded_by`。不存在两份都自称最终值的简报。
- `distribution.compare(id, other)` 给出两版的版本号、状态、逐单元格差异与各自更正记录，订阅者可据此核对两版为何不同。
